## Phase Goal

**As a** user, **I want to** sign in with Google or GitHub on the live stack and stay signed in, **so that** every later feature has a proven foundation.

**This plan's slice:** an operator starts the prod-shape stack and gets a healthy API whose database schema (the Better Auth tables) was migrated automatically at container start (OPS-02). This is the first end-to-end path through DB → migration runner → API → Docker image → compose, and it carries the [BLOCKING] live-schema gate.

<objective>
Create @userhq/db (generated Better Auth schema, pg pool factory, advisory-locked migration runner, first committed migration) and the minimal Nest API (health endpoint with a DB round trip), packaged as a Node 24 image built with Bun and run by compose.yaml in its production shape. Prove on a live Postgres that the boot-time migrate() applies the committed SQL exactly once.

Purpose: resolves the highest-risk build question early (Bun `--filter '@userhq/api...'` + isolated linker + `--production` inside Docker, RESEARCH A4) and establishes the migration contract every later phase relies on.
Output: packages/db source and migrations, API bootstrap, apps/api/Dockerfile, compose.yaml.
</objective>
