## Phase Goal

**As a** user, **I want to** sign in with Google or GitHub on the live stack and stay signed in, **so that** every later feature has a proven foundation.

**This plan's slice:** a visitor opens `/login`, picks Google or GitHub, and is sent to the provider with a return path that cannot be abused. Failed attempts come back to `/login` with a clear, safe message. The same page works in the native dev loop through Caddy.

<objective>
Build the dedicated `/login` page (D-02) with Google and GitHub buttons, `?next=` validation, OAuth error mapping, and pending states exactly as UI-SPEC specifies. Add the first shadcn-style components (Button, Alert) built on individual Radix packages (D-16), and the Caddy dev router for the native dev loop (D-10).

Purpose: AUTH-01 and AUTH-02 on the web side. Phase 3's "prompt sign-in, then return to the same spot" reuses this page and `safeNext`.
Output: login route, client buttons, auth client, safeNext and error-copy modules with unit tests, Button/Alert/provider icons, Caddyfile.dev, Caddy dev service.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL query (?next, ?error, ?error_description) → /login | Attacker-controlled values reach the page |
| browser → provider → /api/auth/callback | OAuth round trip; errors come back as query params |
| host dev servers ↔ Caddy dev container | Dev-only routing over host.docker.internal |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-05-01 | Spoofing | Open redirect via ?next= | high | mitigate | safeNext (relative only; rejects //, backslash, control chars, /api/, /login) used for both the signed-in redirect and callbackURL; unit-tested; Better Auth callbackURL origin check behind it (01-03) |
| T-01-05-02 | Tampering | Reflected XSS via ?error / error_description | high | mitigate | error_description never read; the error code is shown only after the ^[a-z0-9_]{1,64}$ check; copy comes from a fixed table; React escapes output; SSR test with a script payload |
| T-01-05-03 | Spoofing | OAuth login CSRF / state | high | transfer | Better Auth state + PKCE handle it; the client only starts the flow |
| T-01-05-04 | Information disclosure | Caddy dev and Mailpit exposure | low | mitigate | Dev services bind 127.0.0.1 only |
| T-01-05-05 | Elevation of privilege | Better Auth server code bundled into web | high | mitigate | Only better-auth/react is imported; the lint override from 01-01 blocks the rest |
</threat_model>
