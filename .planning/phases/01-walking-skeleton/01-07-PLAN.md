## Phase Goal

**As a** user, **I want to** sign in with Google or GitHub on the live stack and stay signed in, **so that** every later feature has a proven foundation.

**This plan's slice:** a signed-in user uploads an image and gets back a small, metadata-free WebP served from a persistent volume. Anything unsafe or oversized is rejected with a stable error code the UI can explain. The new `uploads` table also proves that a newly added migration is applied automatically on the next API start.

<objective>
Implement UPLD-01 in the API, in the order that matters: multer size limit (D-05) → magic-byte allowlist (D-08) → sharp decode with pixel limit and first frame only (D-06) → resize cap 1600px with EXIF stripped (D-07) → temp write + atomic rename on the uploads volume → DB row → immutable static serving. Add the boot-time volume probe (OPS-01) and the second migration (OPS-02 / ROADMAP success criterion 3).

Purpose: real upload consumers (logos) arrive in Phase 2 and changelog images in Phase 5; both sit on this pipeline and its URL scheme.
Output: uploads module, pipeline, storage, schema + migration 0001, static serving, boot probe, an in-process matrix test, and a prod-shape e2e test.
</objective>
