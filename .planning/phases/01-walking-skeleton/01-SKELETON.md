# Walking Skeleton — UserHQ

**Phase:** 1
**Generated:** 2026-10-01

## Capability Proven End-to-End

A user signs in with Google or GitHub on the Dockerized stack (vinext web and NestJS API behind one origin, Postgres migrated at boot), sees their name and avatar on a server-rendered page, stays signed in across refreshes, and signs out from any page. The same stack accepts a signed-in image upload and serves it back as WebP from a persistent volume.

## Architectural Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Repo shape | Bun-workspace monorepo: `apps/web`, `apps/api`, `packages/db` (API only), `packages/types` (shared Zod contracts) | Shared contracts without publishing; the web image never holds DB code or credentials (CLAUDE.md) |
| Package manager / runtime | Bun 1.4.2 for installs, workspaces and catalogs (isolated linker, exact pins, one reviewed `bun.lock`); Node 24 LTS runs both containers | User decision; Bun runtime rejected over decorator-metadata and VPS-CPU bugs |
| Web framework | Next.js 16 App Router API built by vinext 1.0.0 `output: "standalone"`, run with `node server.js`; `next build` 16.3.8 kept green as a CI canary and escape hatch | Locked; Nitro path has a blocking bug; lint keeps app code builder-neutral |
| Styling / UI kit | Tailwind CSS 4.3.3 via `postcss.config.mjs`; CSS color tokens in `:root` + `@theme inline` (light only, dark-ready); hand-written shadcn-style components on individual `@radix-ui/react-*` packages; Inter via `@fontsource-variable/inter` | D-16, D-17; the `radix-ui` barrel hangs vinext builds |
| API framework | NestJS 12 (Express 5, ESM), global prefix `/api/v1`, Zod contracts from `@userhq/types`, `ApiError {code, message}` envelope | Decoupled backend per PRD |
| Data layer | PostgreSQL 18 + Drizzle ORM 0.45.3 + `pg`; SQL generated by drizzle-kit 0.31.11 at dev time and committed; applied by `packages/db/dist/migrate.js` in the API container CMD under `pg_advisory_lock(727001)` on one connection | User decision; no schema push, no drizzle-kit in prod |
| Auth | Better Auth 1.7.7 inside Nest via `@thallesp/nestjs-better-auth` 2.8.0 at `/api/auth/*`; Google + GitHub OAuth only; DB sessions, 14 days sliding with daily refresh; implicit linking on verified email; library guard disabled in favour of a global default-deny `SessionGuard` (`disableRefresh: true`) plus an `OriginGuard`; the browser-only `SessionKeepAlive` performs the refresh | D-01..D-04; the library guard silently breaks sliding sessions |
| Web ↔ API seam | Same origin with path routing (`/api/*`, `/uploads/*` → api; everything else → web). RSC reads go through `apiServer()`, which forwards only the cookie to `API_INTERNAL_URL`. Browser mutations go through TanStack Query to `/api/v1/*` (no Server Actions). `proxy.ts` does optimistic redirects only | No CORS; authorization lives only in Nest |
| Sign-in UX | Dedicated `/login` with `?next=` validated by `safeNext()`; OAuth errors mapped to fixed copy | D-02; Phase 3 reuses it |
| Uploads | multer 2 MB limit → `file-type` magic-byte allowlist → sharp (40 MP cap, first frame, ≤1600px wide, EXIF stripped) → WebP written to a temp file then atomically renamed to `/uploads/{yyyy}/{mm}/{uuid}.webp` on a named volume → `uploads` row → immutable static serving with `nosniff` and `CSP default-src 'none'` | D-05..D-09; the URL matches the Phase 5 allowlist regex |
| Deployment target | Oracle Ampere A1 (arm64) VPS running Dokploy; one compose app per environment (staging from `main`, prod from `release`), Isolated Deployments on, Traefik path routing and Let's Encrypt; images built on the VPS (no registry) | D-11..D-14, D-18 |
| Release flow | Merge to `main` → Dokploy auto-deploys staging; `v*` tag → CI (reused workflow) → `release.yml` moves `release` to the tag commit → Dokploy deploys prod | D-14; Dokploy's own tag trigger deploys branch HEAD |
| Local environments | Dev: `compose.dev.yaml` (Postgres, Mailpit, Caddy on `http://localhost`) in front of native dev servers. Prod-shape smoke: `compose.yaml` + `compose.local.yaml` (Caddy on `:8080`) | D-10; mirrors prod routing so cookie and redirect bugs surface locally |
| Email | Staging catches mail in Mailpit (compose profile `mail`). Prod uses Brevo SMTP configured only by env. Phase 1 proves reachability with an in-image `smtp-check` CLI and records the port | D-15 |
| Quality gates | oxlint with per-directory import bans and local rules (`no-import-meta-env`, `no-exclusion-columns`); Vitest + SWC for Nest; integration tests on real Postgres; prod-shape e2e suites minting sessions with Better Auth `testUtils`; GitHub Actions CI | ROADMAP Phase 1 lint notes, D-13 |

## Directory Layout Established

- `apps/api/src/{main.ts, app.module.ts, env.ts}`, `auth/`, `uploads/`, `health/`, `common/`, `scripts/`; tests in `apps/api/test/` (in-process) and `apps/api/test/e2e/` (prod-shape stack)
- `apps/web/app/` (routes), `components/ui/` (primitives), `components/` (shell), `lib/` (server and client helpers); `proxy.ts`
- `packages/db/src/schema/*.ts`, `packages/db/migrations/` (+ `meta/`), `packages/db/src/{index.ts, migrate.ts}`
- `packages/types/src/index.ts` (all cross-app contracts)
- Root: `compose.yaml` (prod shape), `compose.local.yaml`, `compose.dev.yaml`, `docker/Caddyfile.{dev,local}`, `.github/workflows/{ci,release}.yml`, `docs/deploy.md`, `tools/` (lint plugin, `signin-evidence.mjs` for the live sign-in gate)

## Stack Touched in Phase 1

- [ ] Project scaffold (framework, build, lint, test runner): plan 01-01, plus 01-02 and 01-04
- [ ] Routing, at least one real route: `/`, `/login`, `/dev/upload`, `/api/v1/me`, `/api/v1/health`, `/api/v1/uploads`, `/uploads/*` (01-02..01-08)

- [ ] UI, at least one interactive element wired to the API: provider buttons, the sign-out menu, the upload form (01-05, 01-06, 01-08)
- [ ] Deployment, running on a real environment: local prod-shape stack (01-04), staging (01-10), prod (01-11)

## Out of Scope (Deferred to Later Slices)

- Workspaces, products, statuses, tenancy guards, platform owner (Phase 2)
- Posts, votes, comments, moderation, email sending and the outbox (Phase 3); Phase 1 only proves SMTP reachability
- Roadmap, notifications (Phase 4); changelog, FAQ, rich text (Phase 5)
- Real upload controls (logos): Phase 2 builds them on the Phase 1 upload API
- External `https:` image URLs in rich text (a Phase 5 decision), srcset widths and per-purpose upload presets, dark mode
- Registry-built images (GHCR): the user deferred any OOM handling beyond swap (D-18)
- Playwright browser E2E, volume backups with a restore drill, publishing the Google consent screen (launch concerns in STATE.md)
- Removing the dev-only upload page: hidden in prod by flag now, removed before launch (D-09)

## Subsequent Slice Plan

Each later phase adds one vertical slice on top of this skeleton without changing its architectural decisions:

- Phase 2: an invited company admin sets up a workspace, team and product portals (tenant resolver, public/admin controller split, logo uploads on the Phase 1 pipeline)
- Phase 3: customers post, vote and comment; commenters get reply emails through Brevo on the port recorded in Phase 1
- Phase 4: admins plan on a private Kanban board and publish a public roadmap that cannot leak internal fields; in-app notifications
- Phase 5: admins publish changelog entries and FAQ answers (Tiptap JSON, WebP images through the Phase 1 upload API)
