# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope (locked, CONTEXT.md D-16/D-17):** a *minimal real shell* that Phase 2 extends rather than replaces. Three surfaces plus global chrome:

1. **Header** on every page (wordmark + user menu with sign-out, or a Sign in button).
2. **`/login`**: Google and GitHub buttons, `?next=` return, OAuth error display.
3. **`/`**: server-rendered home showing the signed-in user's name and avatar (or a signed-out state).
4. **`/dev/upload`**: dev-only, signed-in-only upload test page (2 MB; PNG/JPEG/WebP/GIF).
5. Global **not-found** and **error** pages (needed because `/dev/upload` 404s when disabled).

Light mode only, but every color is a CSS token from day one. Brand, logo, and full visual design are **out of scope**; they come in a later `/gsd-ui-phase`. This contract is deliberately small.

**Mode:** generated under `--auto`. No questions were asked. Every value not locked upstream is marked *(Claude's choice)* and is a default the next UI phase may override.

Canonical values are oklch; hex values are given for reference. *(Claude's choice: brand-neutral until the brand pass. Phase 2+ re-themes by changing variable values only.)*

| Role | Token(s) | Value | Usage |
|------|----------|-------|-------|

| Secondary (30%) | `--muted` | `oklch(0.97 0 0)` #F5F5F5 | Avatar fallback, menu item highlight, outline/ghost button hover, result panel, empty-state panel, Dev-only tag |

| Accent (10%) | `--primary` / `--primary-foreground` | `oklch(0.205 0 0)` #171717 on `oklch(0.985 0 0)` #FAFAFA | See the reserved list below |
| Focus | `--ring` | `oklch(0.205 0 0)` #171717 | Keyboard focus rings only |
| Destructive | `--destructive` | `oklch(0.505 0.213 27.518)` ≈ #C10007 (red-700) | Error alert text, icon, and tinted border/background. *(red-700, not shadcn's red-600, so 14px text clears 4.5:1 on white.)* |

Accent (`--primary`) reserved for, and only for:
1. The fill of the `default` Button variant. In Phase 1 that is exactly one button: **Upload image** on `/dev/upload`.
2. Keyboard focus rings (`--ring` currently equals `--primary`; they stay separate tokens).

Accent is **not** used for: links (they use `--foreground` + underline), the login provider buttons (equal-weight `outline`, so neither provider is visually preferred), the header Sign in button (`outline`), menu items, or headings.

Token rules (for dark-mode readiness, D-17):
- App code uses only semantic utilities (`bg-background`, `text-muted-foreground`, `border-border`, `bg-destructive/5`, …). **No raw palette classes** (`bg-neutral-100`, `text-red-600`, hex literals) in `apps/web`. The provider brand SVGs are the only exception.
- Do not add a `.dark` block, a `@custom-variant dark`, or a theme toggle in Phase 1.
- shadcn's `--accent` / `--secondary` hover tokens are **not** declared. Hover surfaces use `--muted`, so the word "accent" means only the 10% role above.

## Interaction Contracts

### Header and user menu (AUTH-03: "sign out from any page")
- **Signed in:** the trigger is a `Button` `ghost` `icon` (40px, `rounded-full`) wrapping a 32px Avatar, with `aria-label="Open account menu"`.
- **Menu contents, in order:**
  1. Non-interactive `Label` block: the user's name (14px / 600, `truncate`, `max-w-48`).
  2. `Separator`.
  3. *(Only when the dev upload page is enabled; the same server-side flag that gates the route.)* Item `Upload test` with lucide `ImageUp` icon, linking to `/dev/upload`.
  4. `Separator` (only if item 3 is present).
  5. Item `Sign out` with lucide `LogOut` icon.
- **Sign out:**
  - `onSelect` calls `event.preventDefault()`, so the menu stays open while the request runs.
  - The item becomes disabled, shows a `LoaderCircle` spinner, and reads `Signing out…`.
  - On success: `authClient.signOut()` resolves, then a full navigation to `/` (`window.location.assign("/")`), so every RSC re-renders signed-out. This works from any page, including `/dev/upload`.
  - On failure: the item reverts to `Sign out`, and an inline destructive line (14px, `px-2 py-2`, `role="alert"`) appears under it with the sign-out error copy. The menu stays open.
- Sign out has **no confirmation dialog**: it is not destructive.
- **Signed out:** the right side shows `Sign in` (`outline`, `asChild` link) to `/login?next=<current path + search>`. On `/login` itself the right side is empty.
- Keyboard: Radix defaults (Enter/Space/ArrowDown opens, arrows move, Esc closes and returns focus to the trigger).

### `/login` (AUTH-01, AUTH-02, D-02)
- The server component reads `getMe()`. If already signed in, it redirects server-side to `safeNext(searchParams.next)` and never renders the page.
- `next` is validated with `safeNext()`. An invalid value silently falls back to `/`, with no UI message.
- Each button calls `authClient.signIn.social({ provider, callbackURL: safeNext(next), errorCallbackURL: "/login" + (next ? "?next=" + encodeURIComponent(safe) : "") })`.
- **Pending:** the clicked button shows `LoaderCircle` (spinning) in place of the brand mark, and its label reads `Redirecting to Google…` / `Redirecting to GitHub…`. **Both** buttons are disabled until the browser leaves the page. If `signIn.social` rejects or returns an error without navigating, both re-enable and the request-failed alert shows.
- **`?error=` display:** a destructive `Alert` above the buttons and below the description. Copy comes **only** from the mapping table in the Copywriting Contract. `error_description` from the URL is **never rendered**: it is untrusted reflected text. The raw code appears as a muted second line `Error code: {code}`, but only if it matches `^[a-z0-9_]{1,64}$`; otherwise the line is omitted. The error persists until the user clicks a provider button, which clears it from the UI.

### `/` home (AUTH-03)
- An RSC. It reads `getMe()` (React `cache()`, shared with the header) and renders on the server, so the name and avatar are in the initial HTML.
- Signed in: 64px Avatar, h1, body line, and (when the dev flag is on) a text link `Test image uploads →` to `/dev/upload`.
- Signed out: the signed-out state from the Copywriting Contract with a `Sign in` button (`outline`, `lg`) linking to `/login`. The home page is **not** protected by `proxy.ts`.

### `/dev/upload` (UPLD-01, D-05..D-09)
- **Gating:**
  - When the dev flag is off, `notFound()` renders the global not-found page.
  - When it is on, `proxy.ts` redirects signed-out visitors to `/login?next=/dev/upload` (optimistic), and the page RSC also checks `getMe()` and redirects if `user` is null.
- **File input:** native `<input type="file" id="upload-file" name="file">` with a visible `<label for>`.
  - **No `accept` attribute and no client-side type or size check.** The page exists to exercise server validation (SVG, renamed, and oversized files must reach the API). This is intentional; do not "fix" it.
  - Styled with Tailwind `file:` modifiers: `file:mr-4 file:h-9 file:px-4 file:rounded-md file:border file:border-input file:bg-background file:text-sm file:font-semibold hover:file:bg-muted`.
- **Selected-file line** (14px muted, under the input): `{filename} · {size}`. The size is formatted as `{n} KB` below 1 MB, else `{n.n} MB`. The filename is `truncate` with `title={filename}`.
- **Upload image** button (`default` variant): disabled until a file is selected. On click it runs a TanStack `useMutation` that POSTs `multipart/form-data` (field `file`) to `/api/v1/uploads`.
- **Pending:**
  - The button shows `LoaderCircle` and `Uploading…`; the input and button are disabled.
  - The previous result and error are cleared when the upload starts.
- **Success:** the result panel (`bg-muted rounded-lg p-4`, `gap-4`) contains:
  - a success line
  - the preview `<img>` of the returned `/uploads/...webp` URL (plain `<img>`, not `next/image`)
  - a definition list: Format, Dimensions, Size, URL. The URL is a `font-mono text-sm break-all` link with `target="_blank" rel="noopener"`.
  - a `Copy URL` button (`ghost`). After copying it reads `Copied` with a lucide `Check` icon for 2 seconds, then reverts.
  The result stays until the next upload starts. Selecting a new file does not clear it.
- **Error:** a destructive `Alert` between the form and the result area. Copy is chosen by the API error `code` (table below). An unknown code shows the API's `message` if it is a non-empty string under 200 characters, otherwise the generic copy. A `401` additionally renders a `Sign in again` link to `/login?next=/dev/upload`.
- **Empty (before the first successful upload):** a dashed placeholder panel (`border border-dashed border-border rounded-lg p-8 text-center`) with the empty-state copy.

### Global pages
- `app/not-found.tsx`: h1, body, and a `Go to home` button (`outline`, `asChild` link to `/`), inside the normal header + main frame.
- `app/error.tsx` (client): h1, body, and a `Try again` button (`outline`) that calls `reset()`. No error details are shown to the user; the digest is logged to the console only.

### Accessibility (applies to all of the above)
- Focus: every focusable control gets `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2 focus-visible:ring-offset-background`. Never remove focus styles without this replacement.
- Errors pair an icon **and** text; color is never the only signal. Error alerts use `role="alert"`, and the upload success line uses `aria-live="polite"`.
- Spinners are `aria-hidden="true"`; the label text change ("Uploading…") carries the state. Disabled buttons use the `disabled` attribute, not only styling.
- One `<h1>` per page. The document `<title>` follows the Copywriting table.
- Contrast: all text pairs above are ≥4.5:1. The focus ring (#171717 on white) is ≥3:1.

Codes come from Better Auth's OAuth `redirectOnError` (the documented error list) plus the provider's `access_denied`. Confirm the exact codes in the spike; any unlisted code falls back to the last row.

| `?error=` | Alert title | Alert body |
|-----------|-------------|------------|

### Avatar initials rule
Take the first letter of the first two whitespace-separated words of the name and uppercase them (for example "Ada Lovelace" → `AL`, "octocat" → `O`). If there is no letter, show the lucide `User` icon. Never derive initials from the email address; the email is not shown anywhere in Phase 1 UI.

## Out of Scope for This Contract

- Brand identity: logo, brand color, marketing typography. The wordmark is plain text.
- Dark mode, theme toggle, `.dark` tokens (deferred; the tokens are ready).
- Toasts, modals and dialogs, form libraries, drag-and-drop upload, multi-file upload, upload history, deleting uploads.
- Real upload controls (workspace and product logos): Phase 2.
- Sign-in prompt modal or inline auth: never (D-02). Phase 3 reuses `/login?next=`.
- Showing the user's email anywhere.
