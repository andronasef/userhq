## Phase Goal

**As an** invited company admin, **I want to** set up my workspace, team, and product portals, **so that** my customers have a branded place to visit.

**This plan's slice:** the admin side's first path. The platform owner, identified only by the verified config email, creates a workspace and lands in its dashboard. This builds the pieces every admin feature inherits: owner identity, the global validation pipe with UI-SPEC error codes, TenantGuard, the membership table, and the cross-tenant 404 suite.

<objective>
Identify the platform owner from PLATFORM_OWNER_EMAIL plus a verified email (PLAT-01). Let the owner create a workspace with a name and an auto-derived, validated slug (WORK-01, WORK-02) that makes them its owner. Land them on a tenant-guarded /dashboard/{ws}. Then harden the identity rule, prove the owner is not an implicit member, finish the env rollout docs, and start the cross-tenant suite.

Purpose: every admin route from here on sits behind TenantGuard and the validation pipe, and every new :ws route must be added to the cross-tenant suite.
Output: env var + docs, owner helper, members table + migration 0003, workspace create/read API, validation pipe, TenantGuard, /dashboard/new and /dashboard/{ws}, API + cross-tenant + stack tests.
</objective>
