## Phase Goal

**As an** invited company admin, **I want to** set up my workspace, team, and product portals, **so that** my customers have a branded place to visit.

**This plan's slice:** statuses. An admin shapes each product's status list: adds, renames, recolors, and retypes statuses, drags them into the order customers will see, picks where new posts start, and deletes a status only after choosing where its posts go.

<objective>
Build the statuses API (list, add, edit, set default, reorder, delete with replacement) on the 02-08 schema, and the status editor page with Dialog, NativeSelect, ColorField, ConfirmDialog, and a dnd-kit sortable list with keyboard support and live announcements. Cover the reorder backstop with Playwright.

Purpose: STAT-02 to STAT-05. The delete transaction carries marked spots where Phase 3 (posts) and Phase 4 (roadmap items) add their reassignment.
Output: statuses controller, editor page and components, tests (API, cross-tenant, e2e, browser).
</objective>
