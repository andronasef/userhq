# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope:** this phase extends the Phase 1 shell (`01-UI-SPEC.md`, approved). It does not replace it. Every Phase 1 token, component, and copy rule still applies unless this file overrides it. Phase 2 adds four surfaces:

1. **App shell pages** (Phase 1 header + container): `/` landing states, `/dashboard` picker, `/dashboard/new`, `/invite/{token}`, `/platform/*`.
2. **Dashboard shell** (new): `/dashboard/{ws}/...` and `/dashboard/{ws}/{product}/...`. It has a header with a workspace switcher and a left sidebar (D-01, D-03, D-04).
3. **Portal shell** (new, public, branded per product): `/{ws}` directory and `/{ws}/{product}` portal (D-07 to D-11).
4. **Global state pages**: workspace unavailable (suspended), portal unavailable, invite errors.

**Mode:** generated without interactive questions. The orchestrator gave no channel to ask, and 02-CONTEXT.md settles the structural decisions. Values that are not locked upstream are marked *(Claude's choice)*. The user can override any of them before planning.

`lib/accent.ts` (pure, with a unit test) exports `accentTokens(hex)`, which returns `{ primary, primaryForeground, primaryText }`:

- `primary` is the validated hex.
- `primaryForeground` is `#FFFFFF` or `#000000`, whichever has the higher WCAG 2.x contrast ratio against `primary`. A tie goes to white. Pure black is deliberate: with it, the better of the two always reaches at least 4.58:1, so AA text passes for every possible accent. With `#0A0A0A` the worst case drops to about 4.45:1, which fails.
- `primaryText` is `primary` when its contrast against `#FFFFFF` is ≥ 4.5:1. Otherwise it is `#171717`.
- Any input that fails `^#[0-9A-Fa-f]{6}$` returns the default accent's tokens. This is a **security rule**: the value goes into an inline `style`, so an unvalidated string must never reach it.

The test asserts: white text on `#2563EB`, dark text on `#FACC15`, `primaryText` falls back for `#FACC15`, and `"red;}"` returns the default.

**Slug rules that fall out of this map** *(Claude's choice for format, D-01 for the collisions)*:

- Format: `^[a-z0-9]+(?:-[a-z0-9]+)*$`, 2–32 characters, for both workspaces and products.
- Workspace slugs reserve `api`, `dashboard`, `login`, `uploads`, `platform`, `invite`, `dev`, and `new`. `new` is added because `/dashboard/new` sits beside `/dashboard/{ws}`.
- Product slugs reserve `new`, `team`, and `settings`, because they share `/dashboard/{ws}/…` with workspace pages.
- Both lists live in one shared constant in `@userhq/types`.
- Auto-derive a slug from the name like this: lowercase, strip diacritics (NFKD), turn every run of non-`[a-z0-9]` characters into one `-`, trim hyphens, and cut to 32 characters.

## Spacing Scale

These are the same values as Phase 1. All are multiples of 4 and use Tailwind's 4px step.

| Token | Value | Tailwind | Usage (Phase 2 additions) |
|-------|-------|----------|-----------------|
| xs | 4px | `1` | Section label to first item, PageHeader title to description |
| sm | 8px | `2` | Field label to control, badge dot gap, dialog footer button gap, swatch gap, CopyField gap |
| md | 16px | `4` | Status row inner gap, card inner gap, logo-field gap, dialog internal stack, mobile gutters |
| lg | 24px | `6` | Form field stack, card padding, sidebar section gap, danger-zone padding, TabNav tab gap |
| xl | 32px | `8` | PageHeader bottom margin, settings section separation, main vertical padding (mobile), dashboard horizontal padding (≥1024px) |
| 2xl | 48px | `12` | Main vertical padding (≥640px) |
| 3xl | 64px | `16` | Not used in Phase 2 |

Exceptions (fixed component dimensions, all multiples of 4, not spacing tokens):
- Heights: dashboard header 56px, portal header at least 64px, status row 56px, table row 48px, table head 40px, TabNav 40px, sidebar item 36px, inputs 36px, `sm` button 32px, badge 24px.
- Widths: sidebar 240px, mobile drawer 288px, dialogs 448px (confirm) or 512px (form), hex input 128px.
- Logo sizes: 20, 24, 32, 40, and 64px. Swatches are 32px. Status dot in rows: 12px. Badge dot: 8px.
- Touch targets: the drag handle, the row-actions trigger, and the sidebar `+` button are 32px (`size-8`). That is above the WCAG 2.5.8 24px minimum. They sit in 56px rows, so no other control is within 8px vertically.
- `-mb-px` on TabNav tabs, so the active underline overlaps the 1px nav border. This 1px offset is the only sub-4px value allowed.

  - **0 workspaces otherwise:** the invite-only h1 + body. No button.
  - **1 workspace:** server redirect to `/dashboard/{ws}`.
  - **2 or more:** server redirect to `/dashboard`.
- `/dashboard` picker:
  - PageHeader `Choose a workspace`, with `Create workspace` (`outline`) on the right when `canCreateWorkspace`.
  - The list is `rounded-lg border divide-y`. Each row is a full-width link (`flex items-center gap-4 p-4 hover:bg-muted`) holding a 40px `EntityLogo`, a stack (name 16px / 600, `/{slug}` 14px muted mono), and a role `Badge` (`neutral`: `Owner` or `Admin`) pushed right. Rows are sorted by name.

### Create workspace (`/dashboard/new`, WORK-01, WORK-02)
- If the user can't create a workspace, render the invite-only state instead of the form. The page itself does not 404.
- Fields, in order: `Workspace name` (1–50 characters), `URL` (`SlugInput`, auto-derived), and `Logo` (`LogoField`, optional).
- Submit: `Create workspace`. Pending: `Creating…`, with all fields disabled. Success: navigate to `/dashboard/{slug}`, then toast `Workspace created`.
- Slug errors come back from the server by code and show on the URL field (copy below). Other errors show as an `Alert` above the submit button.
- Client-side validation (react-hook-form with the shared Zod schema) runs on blur and on submit. Fields are never validated on every keystroke before the first blur.

### Invite acceptance (`/invite/{token}`, D-13 to D-16)
- **Signed out:** `proxy.ts` and the page redirect to `/login?next=/invite/{token}`. No page is rendered (D-15).
- **Signed in:** the RSC calls `GET /api/v1/invites/{token}` (read-only) and gets `{kind, state, workspaceName?, emailMatches, maskedEmail}`.
  - **Workspace invite, valid and matching:** a client component fires `POST /api/v1/invites/{token}/accept` **on mount**. The page shows `LoaderCircle` + `Joining {workspace}…` (h1 at 16px / 600, `role="status"`). On success it navigates with `window.location.assign("/dashboard/{ws}")`, so the header and switcher re-render. On failure it shows the matching error state below. *(This is how D-15's "accepted on return" is implemented: the state change is a POST that passes the origin check, not a side effect of the GET render.)*
  - **Platform invite, valid and matching:** server redirect to `/dashboard/new`. The invite is consumed only when the workspace is created.
  - **Already a member of the target workspace:** server redirect to `/dashboard/{ws}`. The invite stays unused.
  - **Email mismatch:** the mismatch page. Its actions are `Sign out and switch account` (`default`; signs out, then sends the browser to `/login?next=/invite/{token}`) and `Go to home` (`outline`).
  - **Expired, used, revoked, not found, or workspace suspended:** the matching error page with a `Go to home` button (`outline`). Not found and malformed tokens share one page, which never reveals whether a token existed.
- Masked email format: the first character of the local part, then `•••`, then `@` and the full domain. Example: `a•••@acme.com`.

- When a workspace is suspended, every `/dashboard/{ws}/...` route renders the **workspace unavailable** page *in the app shell*, with no sidebar and no switcher. Its actions are `Go to home` (`outline`) and, when the user has other workspaces, `Switch workspace` (`outline`, links to `/dashboard`).
- Portals (`/{ws}` and `/{ws}/{product}`) of a suspended workspace render the neutral **portal unavailable** page. It has no product branding, no logo, no accent, and no tagline. It uses the app shell with a `Go to UserHQ` link.
- A banned user loses every session immediately. Their next request is signed out. A sign-in attempt returns to `/login?error=account_banned`, which needs the new row in the login error mapping below.

### Portal (`/{ws}/{product}`, `/{ws}`; PROD-03 to PROD-05, D-07 to D-11)
- Both are server-rendered and public. They never render admin UI or admin links (D-01). Signed-in admins get no "Edit" shortcut.
- The website link resolves in this order: the product website, then the workspace website, then omitted. `{company}` is the workspace name.
- `/{ws}` with exactly one live product redirects to that portal. With the directory disabled, it redirects to the workspace website, or 404s when none is set. A deleted or unknown product, or an unknown workspace, gets the normal 404.
- **Metadata:**
  - `<title>`: `{product} · {workspace}`. If the two names are equal (case-insensitive), the title is just `{product}`.
  - `meta description` and `og:description`: the tagline, or the fallback copy.
  - `og:title`: `{product}`. `og:site_name`: `{workspace}`.
  - `og:image` and `<link rel="icon" type="image/webp">`: the absolute URL of the product logo, else the workspace logo. With neither, omit `og:image` and use the default UserHQ favicon.
  - `/{ws}` uses `{workspace}` as its title, and its description is `Products from {workspace}.`

### Accessibility (in addition to Phase 1's rules)
- Every dialog has a title wired to `aria-labelledby` and traps focus (Radix). On close, focus returns to its trigger. After a successful delete, focus moves to the page h1, because the trigger row is gone.
- Swatch radios are reachable with the arrow keys as one tab stop (native radio-group behavior). Each swatch's `aria-label` is the color name. The hex input has its own label, `Custom color (hex)`.
- Disabled menu items that carry a reason keep the reason as visible text, not a tooltip.
- Color is never the only signal. Status rows show the name, every badge carries text, and a suspended state uses both a badge and the word.
- The table is a real `<table>` with `<th scope="col">`. Icon-only buttons all carry an `aria-label`.
- Portal accent: `primaryForeground` always reaches ≥ 4.5:1 on `primary`, and `primaryText` always reaches ≥ 4.5:1 on white (enforced by `accentTokens()`). The focus ring stays neutral, so it always reaches ≥ 3:1.

## Out of Scope for This Contract

- Portal tabs and their content (Feedback, Roadmap, Changelog, FAQ) arrive in Phases 3–5. `TabNav` renders nothing in Phase 2.
- Custom CSS, custom fonts, custom domains, dark theme, and separate favicon or OG uploads (D-12).
- Email delivery of invites (D-14: links are copied by hand). Restoring a deleted product, and suspension reasons (Deferred).
- Approval of email-mismatched invite claims (Deferred).
- Workspace deletion, ownership transfer, roles other than Owner and Admin, and account deletion (WORK-07 is not in this phase's requirement list).
- Skeleton loaders, sortable or filterable table columns, and bulk actions.
