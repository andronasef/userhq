## Phase Goal

**As a** customer, **I want to** post, vote on, and discuss ideas on a product's board, **so that** the team sees what I actually need.

**This plan's slice:** the production half of "commenters get an email" (ROADMAP success criterion 5). Phase 1 never recorded which Brevo port works from the Oracle VPS, and compose.yaml passes no SMTP settings to the API (RESEARCH Pitfall 13). This plan wires the settings through, has a human run the existing probe on the VPS and check Brevo's domain authentication, and records the answer. It runs at the start of the phase so an infrastructure problem surfaces while the code is still being built.

Pass SMTP_* through compose, have a human confirm the working Brevo port and DKIM status from production, and record both in the deploy docs.

Purpose: OPS-03 says email is configured only by environment; production cannot send until the port and sender are known.
Output: compose.yaml, .env.example, docs/deploy.md.
</objective>
