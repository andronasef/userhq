## Phase Goal

**As a** customer, **I want to** post, vote on, and discuss ideas on a product's board, **so that** the team sees what I actually need.

**This plan's slice (the phase tracer, web half):** a signed-in customer opens a product's board, submits a post, lands on its permanent link, and sees it on the board. It runs on the endpoints 03-02 published and proves the riskiest web pieces: the vinext permalink page with a page-level redirect, an author line that can never show an email, and the signed-out round trip through sign-in. The permalink redirect status is a published, one-way contract, so a human decides it (Task 2) before Task 3 ships it.

<objective>
Wire the board, the New post dialog, and the permalink page to the 03-02 API end to end; get the human's decision on the redirect contract; then finish canonical redirects, not-found states, metadata, the signed-out New post round trip, error copy, and the HTML privacy check.

Purpose: POST-01, POST-06, POST-11, AUTH-04 and the New post half of PROD-06, visible in the browser.
Output: board and permalink pages, PostRow, display VoteButton, PostFormDialog, AuthorLine, PlainText, stack e2e.
</objective>

Undo cost: switching the status code after launch leaves cached permanent redirects in browsers for months.</context>
