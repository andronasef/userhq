## Phase Goal

**As a** customer, **I want to** post, vote on, and discuss ideas on a product's board, **so that** the team sees what I actually need.

**This plan's slice:** finding things on the board. Visitors sort, filter, and search, and every view is a shareable URL that the Back button understands (D-11); the list pages with Load more (D-09). It leads with the riskiest unknown in the phase: whether nuqs with `shallow: false` re-renders the server list under vinext, which upstream never tested (Pitfall 12).

<objective>
Prove nuqs-driven RSC refetch first in a real browser, then add search with last-term prefix matching (D-29), category and status filters, the filtered empty state, the mobile toolbar, and cursor-paged Load more.

Purpose: POST-07..10; the merge dialog in 03-11 reuses the same search.
Output: toolbar, client list, search and cursor helpers, statuses in the portal product DTO, API and browser tests.
</objective>
