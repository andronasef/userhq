## Phase Goal

**As an** admin, **I want to** plan privately and share a public roadmap, **so that** users hear back when their feedback moves.

**This plan's slice:** The public-facing experience and user feedback loop. We build the customer-facing public roadmap with responsive mobile tabs and detail modal dialogs, integrate the global in-app notification bell across portal and dashboard headers, build the "My Activity" product feed with update badges, and assert end-to-end zero-leakage in rendered HTML.

<objective>
Ship the public roadmap portal page, in-app notification bell, and "My Activity" feed in `apps/web`, and verify privacy enforcement through automated HTML canary testing.

Purpose: Closes the feedback loop by letting customers see what is planned and get notified when their input leads to product progress.
Output: Public roadmap page, mobile tabs, public item modal, notification bell, activity feed, and automated HTML canary test.
</objective>

| Boundary | Description |
|----------|-------------|
| Public Portal Visitor -> HTML | Anonymous visitors browsing public roadmap pages |
| Signed-in User -> Activity & Notifications | Authenticated session viewing personalized notifications and activity badges |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Information Disclosure | Public Roadmap & HTML Render | high | mitigate | ASVS V14.4 / V4.3: Public roadmap components only receive `PublicRoadmapItem` containing public title, description, and status. Canary tests verify zero presence of planted canary tokens in rendered HTML or client script hydration payloads. |
| T-04-02 | Elevation of Privilege | Activity Feed Access | medium | mitigate | `proxy.ts` redirects unauthenticated visitors to `/login?next=...`. Server-side data fetching ensures activity queries are filtered to `currentUser.id`. |
| T-04-03 | Denial of Service / UI State | Notification Popover | low | mitigate | Popover caps scroll list at `max-h-96` and uses optimistic unread count updates. |
</threat_model>
