# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope:** This phase extends `01-UI-SPEC.md`, `02-UI-SPEC.md`, and `03-UI-SPEC.md` (all approved). It does not replace them. Every Phase 1, Phase 2, and Phase 3 design token, layout rule, accessibility pattern, and copywriting rule still applies unless explicitly superseded here. Phase 4 adds and modifies these user-facing surfaces:

1. **Internal Kanban Board** at `/dashboard/{ws}/{product}/roadmap`: admin-only board with columns per status, dnd-kit drag-and-drop intra- and inter-column reordering, rich item cards with privacy indicators, assignee avatars, deadlines, and linked post counters.
2. **Internal Roadmap Item Modal**: modal dialog for creating and editing roadmap items, toggling public visibility with separate public title and description, assigning members, setting flexible deadlines, and inline searching/linking feedback posts.
3. **Public Roadmap** at `/{ws}/{product}/roadmap`: customer-facing product roadmap tab rendering only public items in admin-selected public status columns (STAT-06). Horizontal multi-column layout on desktop, segmented status tabs on mobile, and a public detail dialog linking to original feedback discussions.
4. **In-App Notification Bell** in both portal and dashboard top navbars: unread count badge, popover listing grouped status-change notifications with public note previews, "Mark all as read" button, and direct navigation to affected posts.
5. **"My Activity" Feed** at `/{ws}/{product}/activity`: portal tab and user dropdown link tracking posts the signed-in user created, voted on, or commented on, displaying visual highlight badges for recent status changes and new comments.
6. **Post-to-Roadmap Linking Controls**: "Add to roadmap" in post admin menus and dashboard header, admin banner showing roadmap link with unlink action on post detail, and disabled status selector while linked.
7. **Status Public Visibility Toggles**: in status settings (`/dashboard/{ws}/{product}/statuses`) and Kanban toolbar quick toggle popover.

**Privacy Barrier Contract (ROAD-12):** Public roadmap views and public API responses strictly exclude all internal fields (`internal_title`, `internal_description`, `internal_notes`, `assignee_id`, `deadline_text`, `deadline_date`). Automated canary tests verify that no canary strings planted in internal fields ever leak into public HTML pages or JSON payloads.

**Mode:** Generated without interactive questions. Decisions D-01 through D-16 from `04-CONTEXT.md` and `REQUIREMENTS.md` fully define the structural and interaction architecture.

## Interaction Contracts

### 1. Internal Kanban Drag-and-Drop
- **Library:** `@dnd-kit/react` 0.5.0 with pointer sensor (activation constraint: 8px drag distance) and keyboard sensor (Space/Enter to lift, arrow keys to move, Space/Enter to drop, Esc to cancel).
- **Positioning:** Fractional rank string (`rank` column).
  - Intra-column move: Recalculates `rank` between above and below neighbors without re-indexing other cards in the column.
  - Inter-column move: Updates `statusId` to target column's status, and calculates `rank` between neighbors at target drop position.
- **Optimistic State:** Cards instantly transition visually to their new position and column.
  - On API error: Reverts to original position and displays error toast: `Couldn't move item. Check your connection and try again.`
- **Screen Reader Announcements:** Live region announcements:
  - `Picked up item "{title}". Column {status}, position {i} of {n}.`
  - `Moved item "{title}" to column {status}, position {i} of {n}.`
  - `Dropped item "{title}" in column {status} at position {i} of {n}.`
  - `Move canceled.`

### 2. Post Linking & "Add to Roadmap" Flow
- **Linking Constraints:**
  - One roadmap item can link to multiple posts (1:many).
  - A post can link to at most one roadmap item (unique constraint on `posts.roadmap_item_id`).
- **\"Add to Roadmap\" from Post:**
  - Available in `PostActionsMenu` on portal and dashboard, plus prominent button on dashboard post detail.
  - Opens `RoadmapItemModal` in create mode prefilled with:
    - `Internal title` = Post title
    - `Internal description` = Post description
    - `Status` = Current post status
    - Pre-linked: Post #{number} listed in linked posts
  - Submitting creates item, links post, and sets post's status to match the item.
- **Status Syncing:**
  - When a roadmap item moves to a new status (via drag or modal edit), all linked posts immediately update their `status_id` to match.
  - When a post's status moves via roadmap sync, post activity log records the change, triggering notifications to post stakeholders (LOOP-03).
  - Linked post status cannot be modified directly from post views; post detail displays `LinkedRoadmapBanner` with an `Unlink` button.
- **Item Deletion:**
  - When a roadmap item is deleted, linked posts retain their current status and unlock cleanly (D-12).

### 3. Public Roadmap Interaction
- **Visibility Filtering:** Renders only items where `is_public = true` AND whose status has `is_public_roadmap = true` (STAT-06).
- **Zero-Leakage Assertion:** Public cards and detail modal render only `public_title`, `public_description`, status badge, and linked public post links. Under no circumstances do internal title, description, notes, assignee, or deadline render.
- **Card Click:** Opens `PublicRoadmapModal` displaying full public text and links to related feedback discussions.
- **Mobile Segmented Tabs:** Below 640px, status columns render as segmented tabs (`nuqs` URL param `?status=...`). Switching tabs reveals that status's items with zero horizontal page scroll.

### 4. Notification Bell & Feed
- **Bell Unread Count:**
  - Fetches unread count on mount.
  - Displays red badge (`size-2`) when unread count > 0.
- **Popover Grouping:**
  - Repeated status changes to the same post are grouped into one notification entry showing the latest status change and public note.
- **Actions:**
  - `Mark all as read`: Sends `POST /api/v1/notifications/mark-read`. Clears unread badge immediately.
  - Clicking a row: Sends read acknowledgment for that post's notifications and navigates to the post.
