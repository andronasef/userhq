## Phase Goal

**As an** admin, **I want to** publish release notes and FAQ answers, **so that** customers see what shipped and can help themselves.

**This plan's slice:** Frontend foundation infrastructure: the safe DOM-free static ProseMirror renderer (`RichTextViewer`), the interactive authoring canvas (`RichTextEditor`) with sticky toolbar and remote image URL insertion, navigation links in `PortalTabs` and `DashboardSidebar`, and server-side API fetchers in `api-server.ts`. This establishes all shared rich-text and navigational primitives for changelog and FAQ screens.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Rich Text AST -> DOM | Rendering untrusted user content without raw HTML execution or XSS |
| Remote Image Insertion | Restricting image sources to valid `http:` and `https:` URLs (D-06) |
| Hyperlink Protocols | Enforcing safe protocols (`http:`, `https:`, `mailto:`) with noopener/noreferrer |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-SC | Tampering | npm dependencies (`@tiptap/*`) | high | mitigate | Approved in package legitimacy audit; installed in Plan 05-01. |
| T-05-07 | Tampering / XSS | `RichTextViewer` rendering | critical | mitigate | Use `@tiptap/static-renderer` native React elements. Forbid `dangerouslySetInnerHTML`. Add `rel="noopener noreferrer nofollow"` to links. (ASVS V5.2 / V5.3) |
| T-05-08 | Tampering | Remote image URL dialog | medium | mitigate | Validate URL protocol (`http:` or `https:`) in input handler before inserting into Tiptap image node. |
| T-05-09 | Denial of Service | Tiptap SSR hydration mismatch | medium | mitigate | Pass `immediatelyRender: false` to all `useEditor` hooks and mark editor components with `"use client"`. |
</threat_model>
