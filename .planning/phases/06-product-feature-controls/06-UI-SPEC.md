# Phase 06 — UI Design Contract

> Visual and interaction contract for Product Feature Controls. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: 06-CONTEXT.md (D-07..D-14), 06-RESEARCH.md (Web Surface, Public Surface Inventory, Open Question 3 and 4), `apps/web/DESIGN.md`, and the existing `apps/web` components read this session.
> This phase adds **no new colors, fonts, sizes, weights or dependencies**. Everything below reuses what `apps/web` already ships.

---

## Decisions Needing User Confirmation

The orchestrator could not ask interactively. Each item below was decided as the option most consistent with the existing UI. Confirm or override before planning; the contract below is written as if every default is accepted.

| # | Decision | Default chosen in this spec | Alternative | Why the default |
|---|----------|-----------------------------|-------------|-----------------|
| U1 | Toggle control and save model | Native checkbox rows plus an explicit "Save features" button (not auto-save, not a switch) | `role="switch"` with immediate save | Matches the `ws-directory-enabled` precedent, needs no dependency, and a Save-button model fits checkbox semantics (a switch implies instant effect) |
| U2 | Confirm on disable | Show the existing `ConfirmDialog` (non-destructive variant) only when a save turns at least one module off. Enabling never asks | Never confirm, or confirm always | Disabling changes what customers see immediately; content is preserved (D-09), so it is a confirmation, not a danger action |
| U3 | All-modules-off root page | Branded neutral state page inside the portal frame, HTTP **200**, `noindex` (Research A1) | 404 via `notFound()`, or 503 | The state is admin-controlled and reversible; 404 makes crawlers drop pages, 503 cannot be set cleanly from an RSC page. `noindex` stops soft-404 indexing |
| U4 | All-off product in the workspace directory | Entry stays and still links to the product root, which shows the unavailable page. No API change | Hide it, or render a non-link card, using a derived `available` flag on the directory payload | CONTEXT says preserve entries unless a reviewed UX rule says otherwise; hiding needs an extra projection field |
| U5 | Single tab | Tab bar is not rendered when fewer than 2 tabs would show | Always render the bar | A one-item tab bar is noise; each page already has an `h1` |
| U6 | Dashboard affordances while a module is off | Sidebar `EyeOff` icon on that module link plus a notice banner at the top of that module's dashboard pages; dashboard links to the public URL of a disabled module are hidden (not disabled) | Disabled-but-visible links | Banner explains why; a disabled link without a reason is worse than no link |
| U7 | Disabled-module direct URL | Uniform generic 404 (existing `app/not-found.tsx`), identical to a nonexistent page. Branded segment-level `not-found.tsx` is a deferred nicety | Add `app/[ws]/[product]/not-found.tsx` | Keeps D-08 "uniform not_found"; avoids revealing that a module exists but is off |
| U8 | Dependency on API shape | Planner must ensure `features` is present on `ProductDetail`, the admin product list item used by the sidebar (`ProductSummary`), and `PublicPortalProduct` | n/a | The sidebar notice and the portal tabs cannot render without it |

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gap inside a badge or sidebar link |
| sm | 8px | Gap between label and helper text, gap between buttons (`gap-2`) |
| md | 16px | Row padding (`p-4`), gap between a checkbox and its text block (`gap-4`), notice padding |
| lg | 24px | Gap between form rows and form sections (`space-y-6`, `mb-6`) |
| xl | 32px | Divider spacing between settings sections (`pt-8 mt-8`) |
| 2xl | 48px | Vertical padding of the all-off state page (`py-12`) |
| 3xl | 64px | Header height (`min-h-16`, existing) |

Exceptions:
- Checkbox rows and the Save button must present a hit area of at least 44px high. Rows use `min-h-11` (44px); with `p-4` they render about 72px. The 16px native checkbox is not the touch target; the whole row is (it is a `<label>`).
- Existing control heights stay as shipped: `h-9` (36px) buttons and inputs, `h-8` (32px) and `h-9` sidebar links.
- Do not introduce 6px or 10px values (existing `gap-1.5` in older components is not a precedent for new code). 12px (`gap-3`) is allowed where the shipped component already uses it.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F6F8F7` (`--background`) | Page canvas in dashboard and portal |
| Secondary (30%) | `#FFFFFF` (`--card`) and `#EAF0ED` (`--muted`) | Feature rows, notice banner (`bg-muted`), portal header |

Accent reserved for:

## Surfaces

### Surface 1 — Dashboard product settings: "Portal features"

**Location.** `apps/web/app/dashboard/[ws]/[product]/settings/page.tsx`. New section between General and Branding, separated like the others: `<div className="border-t border-border pt-8 mt-8">`. The section root has `id="portal-features"` and `scroll-mt-24` so the notice link (Surface 2) lands below the 64px header.

**Structure.**
- `h2` "Portal features" (16px, 600).
- Intro paragraph (14px, `text-muted-foreground`, `id="portal-features-help"`): *"Choose what customers can see for this product. Turning a feature off hides it from your portal and keeps all of its content. You can still manage it here and turn it back on at any time."*
- `<fieldset aria-describedby="portal-features-help" disabled={pending}>` containing `<legend className="sr-only">Features visible to customers</legend>` and four rows in a `flex flex-col gap-2` wrapper (8px between rows).
- Own `useForm`, own `QueryProvider`, own mutation. It PATCHes `/api/v1/workspaces/${ws}/products/${product.slug}` with body `{ features: { board, roadmap, changelog, faq } }` only (never the whole product), parses with `ProductDetailSchema`. Neither `ProductGeneralForm` nor `ProductBrandingForm` may include `features` (Research Pattern 2).

**Row anatomy** (one `<label>` wraps the whole row so the entire row toggles):

```
<label class="flex min-h-11 items-start gap-4 rounded-lg border border-border bg-card p-4 cursor-pointer
              has-[:focus-visible]:outline-2 has-[:focus-visible]:outline-offset-2 has-[:focus-visible]:outline-ring">
  <input type="checkbox" id="feature-{key}" aria-describedby="feature-{key}-desc"
         class="mt-1 size-4 rounded border-border accent-foreground cursor-pointer" />
  <span class="flex min-w-0 flex-1 flex-col gap-1">
    <span class="flex flex-wrap items-center gap-x-2 gap-y-1">
      <span class="text-sm font-semibold text-foreground">{Name}</span>
      {savedOff && <Badge variant="outline"><EyeOff class="size-3 mr-1" aria-hidden /> Hidden from customers</Badge>}
    </span>
    <span id="feature-{key}-desc" class="text-sm text-muted-foreground">{description}</span>
  </span>
</label>
```

Row copy (labels match the dashboard sidebar and portal tabs; the board is "Feedback board" because that is how customer-facing copy already names it):

| Key | Name | Description |
|-----|------|-------------|
| board | Feedback board | Customers submit ideas, vote, and comment. Turning it off also stops customer notifications about feedback. |
| roadmap | Roadmap | Customers see what is planned and in progress. |
| changelog | Changelog | Customers read your release notes. |
| faq | FAQ | Customers search answers to common questions. |

Notes: the badge reflects the **saved** state (`product.features[key] === false`), not the unsaved checkbox, so it never flickers while editing. Rows are listed in the D-13 order (`PRODUCT_FEATURE_KEYS`), which equals the tab order.

**All-off helper.** When all four checkboxes are unchecked (unsaved or saved), render below the rows, before the Save button: a 14px muted line with an `Info` icon (`size-4`, `aria-hidden`), `role="status"`: *"With every feature off, customers see an unavailable page at {host}/{ws}/{product}."* Do not use `Alert` neutral (check-mark icon).

**Actions.**
- `Button` default variant, label "Save features"; disabled unless the form is dirty; pending: `LoaderCircle` spinner plus "Saving…" (same as the General form). `w-full sm:w-auto`.
- Success: `toast.success("Features updated")`, `reset()` to the returned `features`, `router.refresh()` so the sidebar and notices update.
- Failure: `Alert variant="destructive"` above the button with `errorCopy(err)`; the checkboxes keep the user's unsaved choices.

**Confirm-on-disable (U2).** On submit, compute `turningOff = keys that were true and are now false`. If empty, mutate directly. Otherwise open `ConfirmDialog` (`confirmVariant="default"`, `dismissLabel="Keep visible"`, `pendingLabel="Saving…"`, `onConfirm` runs the mutation and throws on failure so the dialog shows the inline error). Dismiss is the auto-focused button (existing behavior). Copy is in the Copywriting Contract.

**States.**

| State | Behavior |
|-------|----------|
| Pristine | Save disabled; checkboxes mirror saved features |
| Dirty | Save enabled; rows show the new checkbox state; badges still show saved state |
| Pending | Fieldset disabled (checkboxes dim), Save shows spinner, dialog (if open) blocks dismissal |
| Error | Destructive alert; fields stay editable; Save re-enabled |
| Cross-tab stale | The PATCH merges only provided keys (Research Pattern 2), so another admin's changes to other modules are not overwritten. After success, `router.refresh()` supplies fresh server state |
| Read-only role | Not applicable: only owners and admins reach product settings; non-members get the existing 404 |

**Keyboard and assistive tech.**
- Tab order: the four checkboxes in tab order, then Save. Space toggles the focused checkbox. Enter in a checkbox does not submit (native behavior); Save is the explicit action.
- Focus ring: 2px `--ring` outline, 2px offset, on the row via `has-[:focus-visible]` (the global base rule covers only `a` and `button`).
- Each checkbox has an accessible name from its label text (Name only, via `aria-labelledby` on the name span if the badge text would otherwise be read into the name) and the description through `aria-describedby`. The "Hidden from customers" badge text is read as part of the row; this is intended.
- After a successful save, focus stays on the Save button; the Sonner toast is a live region. After the dialog closes, focus returns to the Save button (Radix default).
- Touch: rows are at least 44px high and fully tappable; no hover-only affordance.
- Mobile (<640px): rows are full width, badge wraps under the name (`flex-wrap`), Save button full width, no horizontal scroll at 320px. Long descriptions wrap; do not truncate.
- Reduced motion: the dialog and toast use the shared motion tokens (DESIGN.md); the form adds no animation of its own.

### Surface 2 — Dashboard: managing a module that is hidden from customers

Admins keep full access (D-09). The UI makes the hidden state visible and the way back obvious.

**Sidebar** (`components/dashboard/sidebar.tsx`). For each module link (Board, Roadmap, Changelog, FAQ) whose feature is off: keep the link, label and active styling unchanged, and add a trailing icon `EyeOff` (`size-3.5`, `ml-auto shrink-0`, `text-muted-foreground`, `aria-hidden`) plus `<span className="sr-only">Hidden from customers</span>` inside the link and `title="Hidden from customers"` on the link. The Categories page counts as Board and the Statuses page does not get its own icon (statuses are shared by Board and Roadmap). "Settings" and "View portal" are never decorated.

**Notice banner** (new `HiddenModuleNotice`, props `{ ws, product, module }`). Rendered directly under `PageHeader` on these dashboard pages when that module is off: Board (`board/page.tsx`, including post detail `board/[number]` and `categories`), Roadmap (`roadmap/page.tsx`), Changelog (`changelog/page.tsx`, `new`, `[id]`), FAQ (`faq/page.tsx`). Not shown on Statuses or Settings.

```
<div role="status" class="mb-6 flex flex-col gap-2 rounded-lg border border-border bg-muted p-4 sm:flex-row sm:items-center sm:gap-4">
  <Badge variant="outline" class="self-start bg-card"><EyeOff class="size-3 mr-1" aria-hidden /> Hidden from customers</Badge>
  <p class="text-sm text-foreground sm:flex-1">{sentence}</p>
  <Button variant="outline" size="sm" asChild><Link href="/dashboard/{ws}/{product}/settings#portal-features">Turn on in settings</Link></Button>
</div>
```

The sentence is module-specific (see Copywriting Contract). `role="status"` is static content that is present on load, not an announcement; it carries no `aria-live` churn. Mobile (<640px): stacks vertically with the button below the text; the button is `w-full sm:w-auto` so it stays easy to tap.

**Links from the dashboard to a disabled module's public URL are hidden, not disabled (U6).** Rule for the executor: any dashboard link built from `portalHref(ws, product)` + a module path, or `/p/{n}`, renders only when that module is on. Known sites from the research:
- `components/post/post-actions-menu.tsx` "View on portal" item (`/p/{n}`) hidden when Board is off.
- Board dashboard "view on portal" links (`board/board-view.tsx` uses `portalHref`; `components/board/post-form-dialog.tsx:325` uses `portalHref(...)?new=1`): hide or fall back to no link when Board is off.
- Changelog, Roadmap and FAQ dashboard preview links, if any: apply the same rule (executor greps `portalHref` and `/changelog/`, `/roadmap`, `/faq` under `app/dashboard` and `components/dashboard`).
- Sidebar "View portal" and the overview card link go to the product root, which always resolves (landing fallback or unavailable page). Keep them.

### Surface 3 — Portal navigation, landing and directory

**Tabs** (`lib/portal-features.ts` `portalTabs(ws, product, features, hasUser)`, rendered by `PortalTabs`).
- Order and labels, shown only when enabled: Feedback (`/{ws}/{product}`), Roadmap, Changelog, FAQ, then Activity only when `features.board && hasUser`.
- If the result has fewer than 2 tabs, the layout passes no `tabs` to `PortalFrame` (no empty bar, no one-item bar) (U5).
- The active tab logic is unchanged. A tab for a module that was just disabled on another device still exists until the next navigation; clicking it yields the uniform 404 (Research: handle availability on refresh). No client polling.
- Keyboard and touch are inherited from `TabNav` (horizontal scroll with `no-scrollbar`, 40px tall links, `aria-current="page"`); at most 5 tabs, so the existing mobile scroll suffices.

**Landing (portal root, `app/[ws]/[product]/page.tsx`) — D-13.**
1. Board on: render the board exactly as today.
2. Board off: `redirect()` (307, never a permanent redirect) to the first enabled of Roadmap (`/roadmap`), Changelog (`/changelog`), FAQ (`/faq`).
3. None enabled: render the unavailable state (Surface 4).
- The logo/name link in `PortalFrame` (`homeHref`) always points to the root and therefore always resolves.
- Metadata: `generateMetadata` on the board page returns `{}` when Board is off so the title falls back to the layout title.

**Layout description fallback** (`generateMetadata` in `[product]/layout.tsx`, used when the product has no tagline). Deterministic, from `portalDescription(name, workspaceName, features)`:
- Board and Roadmap on: existing string, unchanged (D-11): *"Share feedback, vote on ideas, and follow what's coming next for {name}."*
- Otherwise the first enabled in D-13 order: Board *"Share feedback and vote on ideas for {name}."*, Roadmap *"See what's planned for {name}."*, Changelog *"Read what's new in {name}."*, FAQ *"Find answers to common questions about {name}."*
- None enabled: *"{name} from {workspaceName}."*
The tagline, when present, always wins (unchanged). Open Graph and Twitter titles and the logo/icon are unchanged: branding metadata stays public.

**Workspace directory** (`app/[ws]/page.tsx`, `ProductCard`). No visual change (U4). Cards link to the product root, never to a module path. A single-product workspace still redirects to that root, which may then show the landing fallback or the unavailable page.

### Surface 4 — Unavailable page for a product with every module off

- Rendered by `app/[ws]/[product]/page.tsx` when no module is enabled, inside the normal branded `PortalFrame` (logo, name, tagline, accent, "Back to {company}" link, notification/sign-in controls, "Powered by UserHQ" footer). No tabs.
- Content: `StatePage` in the standard portal container (`mx-auto max-w-3xl`, `py-12`), `h1` plus one sentence, plus an optional action.
  - If `websiteUrl` is set (the product website, or the workspace website fallback already resolved by the portal): `Button variant="outline"` "Visit {companyName}" (opens in the same tab).
  - Otherwise no action.
- HTTP 200, `robots: { index: false, follow: false }` in `generateMetadata` (U3). Do not use the suspended-workspace page's AppShell; this state keeps the tenant's brand.
- No sign-in prompt, no mention of "disabled", "off", "features" or any module name, and no admin hint (the page is public). Admins who see it can reach settings from the dashboard.
- Reaching `/roadmap`, `/changelog`, `/faq`, `/p/{n}` or `/activity` on such a product is the uniform 404 (Surface 5), not this page.

### Surface 5 — Direct URL to a disabled module

- Pages: `roadmap/page.tsx`, `changelog/page.tsx`, `changelog/[slug]/page.tsx`, `faq/page.tsx`, `activity/page.tsx`, `p/[ref]/page.tsx`. Each checks the product's `features` first and calls `notFound()`; the API already returns `not_found`.
- The visitor sees the existing generic page: `h1` "Page not found", body "The page you're looking for doesn't exist or has moved.", `Button` outline "Go to home" (`app/not-found.tsx`). Identical for disabled and nonexistent pages (U7); no module name, no hint.
- HTTP status 404 (Playwright asserts `response.status() === 404`).
- `generateMetadata` for these pages returns `{}` when the module is off so no module title leaks into the document title.

### Surface 6 — Suppressed links, previews and nested content

Server projections already strip the data (Research N1..N10). The UI contract below says what the executor renders when that data is absent.

| Where | Rule when the related module is off |
|-------|-------------------------------------|
| FAQ empty state (`faq-portal.tsx`, "No frequently asked questions yet") | Board off: render without the "Explore feedback" action; keep title and body |
| FAQ "Didn't find what you were looking for?" prompt (`FaqNotFoundPrompt`, rendered both at the end of the list and as the zero-results state) | Board off: do not render it at all. For zero search results render a plain muted block (`rounded-lg border border-border bg-muted/30 p-6 text-center`) with heading "No answers match your search" and body "Try different words or clear the search." |
| Roadmap empty state (`public-roadmap-board.tsx`) | Board off: body becomes "Check back later to see what we're working on." and the "View feedback board" button is not rendered |
| Roadmap card idea count and modal "linked ideas" list | Board off: the API returns `postCount: 0` and no posts; render no count line and no section. With Board on, existing behavior is unchanged |
| Feedback post page "linked roadmap item" banner (`LinkedRoadmapBanner`) | Roadmap off: API returns `roadmapItem: null`; render nothing |
| Notification bell and My activity | Board off: server filters rows; the unread badge excludes hidden items; the Activity tab is absent; a user with no visible items sees the existing empty state |
| Unsubscribe page | Always reachable; with Board off the API returns no post title or URL, and the page keeps its existing `this post` fallback (no UI change) |
| Portal header controls (sign-in, user menu, bell) | Unchanged in every combination |
| Re-enable | No UI work: links return when the flag returns. Notifications suppressed while off are not replayed (D-14) |

Link rule for any other customer-facing link into a module: render it only when that module is on. The executor treats a missing `features` prop as a build error (required prop, no default of "all on") so a future component cannot fail open.

### Surface 7 — Keyboard, accessibility and mobile summary

- All new interactive elements are native (`input`, `button`, `a`); no custom ARIA widgets and no focus traps beyond the existing Radix alert dialog.
- Focus indicators: 2px `--ring` outline with offset on every new control (global `a`/`button` rule; explicit `has-[:focus-visible]` on checkbox rows).
- Target size: 44px minimum for checkbox rows; existing 32 to 40px controls elsewhere are unchanged.
- Color is never the only signal: hidden state uses an icon plus the text "Hidden from customers" (visible in the badge, `sr-only` in the sidebar).
- Reduced motion and dialog/toast motion follow DESIGN.md; this phase introduces no new animation. Portal tab fade (`PortalSectionMotion`) is unchanged.
- Widths from 320px: no horizontal scroll; the notice stacks; rows wrap; the state page text wraps and the product name in the header truncates as today.
- Long product or workspace names: `PortalFrame` already truncates; the state page and dialog copy interpolate the name and must wrap (`break-words`).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (settings) | Save features |
| Primary CTA (notice) | Turn on in settings |
| Section heading | Portal features |
| Section intro | Choose what customers can see for this product. Turning a feature off hides it from your portal and keeps all of its content. You can still manage it here and turn it back on at any time. |
| Hidden badge | Hidden from customers |
| All-off helper (settings) | With every feature off, customers see an unavailable page at {host}/{ws}/{product}. |
| Save success toast | Features updated |
| Save error | Uses `errorCopy(err)`. Fallback when no mapped copy exists: "We couldn't save your changes. Check your connection and try again." |
| Empty state heading (customer, all-off) | Nothing is available here right now |
| Empty state body (customer, all-off) | {Product name} isn't open to visitors at the moment. Please check back later. |
| Empty state action (customer, all-off, optional) | Visit {companyName} |

| Roadmap empty body, Board off | Check back later to see what we're working on. |
| Destructive confirmation | None. No destructive action exists in this phase; nothing is deleted when a module is turned off. See the confirm dialogs below, which use the non-destructive variant |

**Dashboard notice sentence by module** (14px, one sentence):

| Module | Sentence |
|--------|----------|
| Board | Customers can't see the feedback board, post ideas, or get notified about feedback. Your posts and comments are kept. |
| Roadmap | Customers can't see your roadmap. Your roadmap items are kept. |
