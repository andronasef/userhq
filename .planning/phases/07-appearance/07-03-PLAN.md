# Plan 07-03: Appearance Tests and Verification

## Context & Purpose
Ensure appearance preferences behave deterministically and without visual regressions:
1. Unit tests test the theme resolution algorithm, storage interactions, and default system fallbacks.
2. Playwright browser tests verify:
   - Default is system theme.
   - Visitor selecting Dark theme adds `.dark` class to `<html>` and updates theme custom properties.
   - Reloading the page retains Dark mode with zero white flash (no FOUC).
   - Visitor selecting Light theme removes `.dark` class.
   - Preference is remembered across navigation between public portal and admin dashboard.
   - Theme toggle controls are accessible and functional on both 320px mobile and 1440px desktop screens.

## Implementation Details

1. **Unit tests in `apps/web/test/theme.test.ts`**:
   - `resolveEffectiveTheme('system', false)` -> `'light'`
   - `resolveEffectiveTheme('system', true)` -> `'dark'`
   - `resolveEffectiveTheme('light', true)` -> `'light'`
   - `resolveEffectiveTheme('dark', false)` -> `'dark'`
   - Storage serialization / parsing edge cases.

2. **Browser E2E test in `apps/api/test/browser/appearance.spec.ts`**:
   - Visit public portal (`/[ws]/[product]`) as guest.
   - Verify initial document theme attribute and absence of `.dark` when system is light.
   - Click theme toggle -> select Dark.
   - Verify `<html>` has class `dark`.
   - Verify computed style of `document.body` background is `#0b111e` (or dark navy token).
   - Reload page -> verify `.dark` class is present immediately.
   - Navigate to `/dashboard` -> verify `.dark` is preserved.
   - Switch back to Light -> verify `.dark` class removed.

3. **CI Check**:
   - Run `bun run typecheck`, `bun run test`, and `playwright test test/browser/appearance.spec.ts`.

## Verification
- All tests pass cleanly.
