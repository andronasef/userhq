# Plan 08-02: Workspace Feedback Inbox API Endpoints & Services

## Purpose
Build backend endpoints and domain services for:
1. `GET /api/v1/workspaces/:ws/requests`: Cross-product requests feed with product context, filtering by product, category, status type/ID, sorting by top/new/activity, search, and pagination.
2. `GET /api/v1/workspaces/:ws/comments`: Cross-product comments feed with product & post context, filtering by attention (needs_attention vs handled), unread state, pagination, and count of needs_attention.
3. `POST /api/v1/workspaces/:ws/comments/:id/handled`: Mark comment handled by current user.
4. `DELETE /api/v1/workspaces/:ws/comments/:id/handled`: Reopen comment attention.
5. `POST /api/v1/workspaces/:ws/comments/:id/reply`: Direct admin reply to customer comment (automatically marks comment thread handled).
6. `POST /api/v1/workspaces/:ws/comments/:id/read`: Mark comment read for the current user.

## Implementation Details
1. **Service (`apps/api/src/feedback/workspace-feedback.service.ts`)**:
   - Queries `posts` joined with `products`, `statuses`, `categories`, `user`, counting comments.
   - Respects workspace tenancy boundary (`products.workspaceId = tenant.workspaceId`).
   - Supports search (tsvector or text match), status filtering (by statusId or status standard type e.g. open/in_progress/completed), category filtering, product filtering.
   - Queries `comments` joined with `posts`, `products`, `user`, `commentReads` for user unread state.
   - Attention logic:
     - "needs_attention": non-admin comments (`isAdmin = false`) that are not soft-deleted and `handledAt IS NULL`.
     - "handled": comments where `handledAt IS NOT NULL` or replies that resolved attention.
   - Reply creation:
     - Creates admin comment under post, links `parentId` if replying to specific comment, marks target comment (and unhandled customer comments in post) as handled!
2. **Controller (`apps/api/src/feedback/workspace-feedback.controller.ts`)**:
   - Scoped under `@Controller("workspaces/:ws")`, guarded by `TenantGuard`.
   - Serializes responses using schemas from `@userhq/types`.
3. **Register in `FeedbackModule` (`apps/api/src/feedback/feedback.module.ts`)**:
   - Add controller and service.
4. **Behavior-First Tests (`apps/api/test/workspace-feedback.spec.ts`)**:
   - Unit & integration tests testing cross-product request filtering, comment attention filtering, marking handled, reopening, replying, and unread states.
