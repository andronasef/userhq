# Outbound security review

Scope: `fb3a052...f840523`; test evidence strengthened in the subsequent quick-task commit.
Ask-matt's independent standards and spec reviewers inspected the changes separately.

## Standards

No material findings. Reviewed address classification, URL normalization, DNS
revalidation and pinning, TLS identity, proxy/socket isolation, redirects,
DNS-through-body deadlines, response bounds and worker status handling. Installed
web-push source confirms the generated POST headers/body preserve the wire format.

## Spec

No blocker; two warnings:

1. The plan called for destination validation before generating encrypted push
   details. The implementation generates these bytes locally, then validates in
   the sole network transport. Accepted implementation deviation: this performs
   no network I/O before validation and retains one DNS-through-response budget,
   avoiding duplicate DNS validation budgets. Invalid encryption keys may fail
   before DNS policy evaluation, but cannot cause a request to any destination.
2. Initial tests checked the pinned callback once and only validated an IPv6
   literal without delivering. Addressed with repeated callback checks and an
   IPv6-literal native HTTPS boundary test using a real TLS receiver with an IP
   SAN. The test adapter routes only test sockets to loopback, asserts original
   native request options, and checks the original literal against the certificate.
   A mismatched IP certificate is rejected. Production has no routing exception.

The reviewer also noted that the new expiry test exercises 410; 404 shares the
same explicit implementation branch and was inspected, not separately exercised.

## Outcome

Standards: zero findings. Spec: zero blockers, one evidence warning resolved,
one documented local-computation ordering deviation accepted. No material
security defect remains from this review. Focused final suites pass 130 tests.
The primary agent made and verified the small evidence correction without a
second delegate review.
