# Phase quick-261107-1a5 Plan 01: Inbox reply, attention state and feed fixes Summary

Inbox replies now go through the same creation path as portal replies, any admin reply resolves the customer thread with attribution, existing data is repaired by a committed idempotent backfill, and the inbox feeds page by validated keyset cursors with date and category filters and an accessible comments UI.

## What changed

1. **Shared reply path (task 1, tracer).** `WorkspaceFeedbackService.replyToComment` keeps its tenant-scoped lookup and then delegates to `CommentsService.createComment`. Reply-to-reply folds to the thread root, email respects the Board switch (D-09/D-10), merged posts return 404 `post_not_found`, one webhook delivery is emitted, API keys still stamp `createdByApiKeyId`. Inside `createComment`, an admin reply with a resolved parent marks the root and its direct unhandled customer replies handled by that admin, in the same transaction.
2. **Handled state, cursors, filters (task 2).** `markCommentHandled` only updates unhandled rows. Deleted handlers are returned as `deleted: true`. `cursor.ts` gained `encodeKeysetCursor` / `decodeKeysetCursor` (Zod strict, kind-bound, timestamp range and real-date checks, int32 vote bound, uuid id); every failure is 400 `validation_failed`. Requests (new/top/activity) and comments use row-value keyset predicates on the page query only; counts are unaffected. `createdFrom` / `createdTo` (UTC) added with a reversed-range check; reply body uses the trimming `CommentBodySchema`; cursor length capped at 512.
3. **Migrations (task 3).** `0018_comment_attention_index.sql` (generated partial index `comments_needs_attention_idx`, predicate identical to the service filter) and `0019_backfill_comment_attention.sql` (single `WITH ... UPDATE`, handles unhandled customer comments that have a later non-deleted admin comment in the same thread, earliest admin wins, idempotent, no DDL or deletes). Proven by an upgrade test that migrates real rows across the boundary.
4. **Comments view (task 4).** Native "Mark as read" button (aria-label includes author and post title) with optimistic update and rollback plus error toast; Reopen hidden for admin comments; "Handled by a former member" for deleted handlers; `applyReplyToFeed` updates the feed and count after a reply, then `router.refresh()` pulls thread-mates resolved server-side.
5. **Requests view (task 5).** Native date range inputs ("Created from (UTC)" / "Created to (UTC)"), category select (disabled without a product, cleared on product change), exported `buildRequestsQuery` used by load more, exported `LoadMoreFooter` with `role="alert"` and "Try again". Page, `api-client` and `api-server` pass `categoryId`, `createdFrom`, `createdTo`; categories load for the selected product.

## Deviations from Plan

**1. [Rule 2 - Correctness] Index column ordering.** drizzle's `.desc()` emits `DESC NULLS LAST`, which does not match the query's `ORDER BY ... DESC` (NULLS FIRST), so the planner could not use it for ordering. The schema uses `.desc().nullsFirst()`; generated SQL carries `DESC NULLS FIRST` and the same WHERE predicate. Commit 70ce783.

**2. [Rule 1 - Bug] Test-only fix.** A `disabled` substring assertion matched Tailwind's `disabled:` classes; the test now asserts the `disabled=""` attribute. Commit ae0cfd9.

**3. [Rule 1 - Regression guard] Toast copy.** The existing browser spec (`apps/api/test/browser/workspace-dashboard.spec.ts`) asserts "Reply posted and marked handled", so that text was kept (commit 6057539) rather than rewording it as the plan hinted.
