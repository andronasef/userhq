Structure and decisions (Claude's discretion, recorded here so the SUMMARY can cite them):
- Tasks are ordered tracer-first by dependency, not as the suggested A/B/C grouping, because types/db must exist before the API compiles and each commit must typecheck. Task 1 (tracer) is the public attribution slice end to end (web, API, cookie, bind). Task 2 is the admin/rule model, standards and tests. Task 3 is docs and the final gate.
- No portal-scoped "/me" exists (/me is not product-scoped, and the portal layout's server-side fetch cannot return Set-Cookie to the browser, so a GET-time bind could never clear the cookie and a revoked badge could be re-granted by a stale cookie). The "authenticated portal session fetch" bind is therefore the browser-originated attribute call that PortalBadgeAttribution makes on every portal page mount, plus the interceptor on create post, create comment and put vote.
- The client cannot know rule param keys (they are server-only; exposing them is a privacy regression). Scrubbing is two-stage: signature params ({key}_sig with {key}_ts and the base key present) are removed from the URL before the request; keys the server matched are named in the response (scrubKeys, only keys the caller itself sent) and removed on response.
- Adjacent defects found while verifying, fixed here because tests cannot pass without them: every admin-side badge fetch in the web app (settings form, users manager) uses an unversioned API path and 404s; apps/api/test/badges.test.ts uses an unversioned path, a non-existent testApp.server property, no Origin header and asserts the secret token is echoed back; invalid bodies currently surface as 500 because a raw ZodError is thrown; the users directory returns email to API-key callers (contradicts the workspace-feed policy); lookups by param key on a plain object are prototype-unsafe.
- HY2-13 (badge filter on dashboard inbox/requests feeds; badges on public feed lists) is DEFERRED, pre-authorized by the task description. Reasons: public board list rows carry no author field at all, so adding one is a new public-data decision rather than a fix; workspace feeds span many products while badges are product-scoped, so a filter needs a cross-product badge picker and a tenant-verified query on two feeds; and it would push this plan past its context budget. The executor records it in the SUMMARY and marks the spec line as not yet shipped.
- Do not add dependencies. No new package installs; cookie parsing is a few lines.
