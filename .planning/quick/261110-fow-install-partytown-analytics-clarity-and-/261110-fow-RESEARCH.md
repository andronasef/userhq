## Grounded facts

- `apiFetch` in `apps/web/lib/api-client.ts` centralizes browser API calls, response handling and errors. It is a natural relay for server-confirmed safe receipts without duplicating success events in every component.
- `req.tenant` contains authenticated workspace/product/role after the guard. `req.portal` contains workspace/product but not role; current-workspace membership must be resolved for public contributor operations. API-key users use `integration:` principals.
- Better Auth OAuth is in `apps/api/src/auth/auth.ts`; browser auth is not routed through apiFetch. Accurate sign_up/login needs real lifecycle evidence, not every /me call or timestamp guessing.
- A single root layout owns page lifetime, so unmounting a Clarity component alone cannot undo a recorder initialized on public DOM. Public/private SPA navigation needs a proven document/observer boundary.
- Notification email links are generated by email worker/render helpers; push destination URLs are generated by PushService and opened by the existing service worker. Bounded channel/type markers can preserve destination hashes without tracking recipient tokens.
- Existing privacy copy in all 13 dictionaries says only sign-in cookies/no cross-site tracking; provider disclosures must change with installation.
- Runtime is Node 24, Bun only package manager; vinext standalone is the required production build. No raw Next worker strategy or Vite-only env APIs in app code.

## Official provider constraints

- Partytown needs same-origin `/~partytown/` library files; integrate copying into dev and build. https://partytown.qwik.dev/copy-library-files/
- Forward `dataLayer.push` so browser events reach worker-loaded GTM. https://partytown.qwik.dev/forwarding-events/
- GA4 supports CORS without a broad application proxy; worker exit `user_engagement` is unreliable and must not be the core success metric. https://partytown.qwik.dev/google-tag-manager/
- Clarity and New Relic are not in the listed tested common services; worker compatibility must be demonstrated rather than assumed. https://partytown.qwik.dev/common-services/
- New Relic recommends the browser agent near the top of head; delayed/global wrapping affects early instrumentation. Keep error/performance observation in the page context. https://docs.newrelic.com/docs/browser/browser-monitoring/installation/install-browser-monitoring-agent/
- Node APM ESM startup uses the package loader plus preload before application modules. https://docs.newrelic.com/docs/apm/agents/nodejs-agent/installation-configuration/install-nodejs-agent/
- GA4 User-ID is an opaque identifier, must clear on logout; no names/emails. https://developers.google.com/analytics/devguides/collection/ga4/user-id?platform=websites
- No GA4 G-ID or Measurement Protocol API secret was supplied, only the GTM container. Account publishing cannot be performed or claimed without authorized account access.
- Do not treat GA event logs as exact current backlog. Query existing DB for unanswered/current-state operational reports and document cohort/event windows separately.

## Accepted scope

Only the analytics/error/replay capabilities selected in the conversation are in scope. No advertising, ecommerce, consent UI, analytics UI inside UserHQ, API credential dashboards, vendor account automation, deployment or release.
