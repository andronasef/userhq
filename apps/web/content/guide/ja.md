## 概要とワークスペース構造

UserHQは、チームがユーザーからのフィードバックを収集し、迅速に対応できるよう支援します。ワークスペースの構成は以下の通りです：

<cards>
- **1. Workspace（ワークスペース）**：チームの中核拠点。チームメンバー、請求管理、APIキー、Webhook、全製品横断のフィードバック受信トレイを統合管理します。
- **2. Products（プロダクト）**：開発・提供する個々のアプリやサービス（例：Webアプリ、iOSアプリ、API）。製品ごとに個別のフィードバックボード、ロードマップ、チェンジログ、カテゴリー、ブランド設定を持ちます。
- **3. Customer Portals（カスタマーポータル）**：ユーザーがアイデアを投稿し、機能要望に投票し、公開ロードマップを確認し、リリース告知を読むためのブランドポータルです。
</cards>

<!-- section: roles-permissions -->
## 役割とチーム権限

ワークスペースの重要設定に対する安全な管理を保ちながら、チーム全体でスムーズにコラボレーションできます：

<cards>
- **Workspace Owner（オーナー）**：全権限：サブスクリプション管理、管理者の招待、APIキーの作成、Webhookの設定、所有権の譲渡。
- **Workspace Admin（管理者）**：製品設定の管理、フィードバックのトリアージ、ユーザーへの公式返信、ロードマップカードの管理、リリースノートの公開。
- **Workspace Member（メンバー）**：投稿されたフィードバックの閲覧、チーム内ディスカッションへの参加、ユーザー要望のトラッキング。
</cards>

<!-- section: requests-inbox -->
## 要望一覧（全ボード）とトリアージ

`/dashboard/[ws]/requests` にある統合受信トレイでは、全プロダクトに寄せられたユーザーからの投稿をひとつの高性能なトリアージビューに集約します。

<cards>
- **多次元フィルター**：プロダクト、ステータスフェーズ（バックログ、進行中、完了）、カテゴリー、キーワード検索、日付範囲で即座に絞り込み。
- **スピーディなステータス変更**：ワンクリックでフェーズを移動（検討中、計画済み、開発中、完了）。投票したユーザーには自動で通知が届きます。
</cards>

<!-- section: comments-attention -->
## コメントと要対応（Needs Attention）受信トレイ

`/dashboard/[ws]/comments` にあるこの受信トレイは、フィードバックスレッドに対する迅速なサポートデスクとして機能します。

### ワークフローステージ

<stages>
- **Needs Attention（要対応）**：チームからの公式返信がまだ行われていないユーザーコメント。アンバーカラーのインジケーターで強調表示され、見落としを防ぎます。
- **Handled（対応済み）**：チームメンバーが公式バッジ付きで返信すると自動で要対応キューから外れます。手動で対応済みに切り替えることも可能です。
</stages>

<!-- section: author-location -->
## 投稿者連絡先と位置情報のインサイト

フィードバックを投稿したユーザーの背景を把握できるように、リクエストカードやコメントカードには投稿者の詳細情報が表示されます：

- **メールでのダイレクト連絡**：投稿者名の横にあるメールアイコンをクリックして、ユーザーインタビューやヒアリングの連絡を迅速に行えます。
- **地理的コンテキスト**：ユーザーのおおよその所在地（例：`London, United Kingdom [GB]`）を確認し、地域別の利用傾向を把握できます。
- **プライバシー配慮の設計**：投稿者のメールアドレスや所在地はワークスペースのチームメンバーにのみ表示され、公開ポータルに露出することはありません。

<!-- section: customer-portals -->
## 公開カスタマーポータル

ワークスペース内のすべてのプロダクトは、`/[ws]/[product]` に専用の公開ポータルを持つことができます。

<cards>
- **モジュール式機能切り替え**：フィードバックボード、ロードマップ、チェンジログ、FAQの各機能をプロダクトごとに個別に有効化・無効化できます。
- **カスタムブランディングとテーマカラー**：ロゴ、ブランド名、カスタムアクセントカラーを設定し、サービスの世界観に合わせたデザインを構築できます。
- **多言語対応とRTL**：訪問者言語の自動検出、言語セレクター、13言語での多言語コンテンツ作成に対応しています。
- **デフォルト言語の切り替え**：既存の翻訳がメインフィールドに引き上げられ、元のテキストは代替翻訳として保持されます。
- **ユーザーバッジ**：投稿やコメントの横にバッジを表示して主要ユーザーを認知できます。手動または属性ルールで自動付与できます。
</cards>

<!-- section: roadmap-changelog -->
## ロードマップ計画とリリースノート

<cards>
- **インタラクティブ・ロードマップ**：機能開発の進捗を視覚的なカラム（検討中、計画済み、進行中など）で整理し、ユーザーのフィードバックを直接カードに紐付けます。
- **チェンジログとリリース発表**：カテゴリー別（新機能、改善、不具合修正）のリリースノートを公開し、要望を出したユーザーへ自動で完了報告を行えます。
</cards>

<!-- section: faq-system -->
## セルフサービスFAQナレッジベース

プロダクトポータルにカテゴリー分けされたよくある質問を追加できます。即座に疑問を解消することで、重複した要望や一般的な問い合わせを削減します。

<!-- section: themes-push -->
## テーマとWeb Push通知

UserHQには4つのテーマが用意されています：**システム連動**、**ライト**、**ダーク**（ディープネイビー）、**チャコール**（ニュートラルなブラック）。チームメンバーは `/account` でWeb Push通知を有効化できます。

<!-- section: api-overview -->
## 自動化APIと認証

UserHQ REST Automation APIを使用して、外部システム、CI/CDパイプライン、Slack、Discord、Linear、GitHub、社内ダッシュボードと連携できます。

### 認証ヘッダー

```http
Authorization: Bearer uhq_live_xxxxxxxxxxxxxxxxxxxxxxxx
```

<cards>
- **レート制限**：APIキーあたり毎分120リクエストの十分なクォータをトークンバケット方式で提供します。
- **スコープ権限**：キーを特定のプロダクトに限定し、特定リソースへの読み取り／書き込み権限を細かく制御できます。
</cards>

## WebhookとHMAC署名検証

UserHQは、リクエストの作成、ステータス変更、コメント投稿時にリアルタイムでHTTP POSTイベントを配信します。すべての配信には `x-userhq-signature` ヘッダーに安全なHMAC-SHA256署名が含まれます。

### Node.js / Express HMAC署名検証サンプル

```typescript
import crypto from "crypto";

export function verifyUserHqWebhook(rawBody: string, signatureHeader: string, secret: string): boolean {
  const expectedSignature = crypto
    .createHmac("sha256", secret)
    .update(rawBody)
    .digest("hex");

  const expectedHeader = `sha256=${expectedSignature}`;
  return crypto.timingSafeEqual(
    Buffer.from(signatureHeader),
    Buffer.from(expectedHeader)
  );
}
```
